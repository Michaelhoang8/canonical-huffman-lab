# Measurement methodology

## Scope

The experiment compares this repository's Python canonical Huffman byte codec with `zlib.compress(data, level=9)` and the corresponding decoders. It measures complete encoded file size and in-memory call time. It does not isolate the effect of the compression algorithm from implementation language, validation work or library engineering.

zlib's default Python interface produces a wrapped zlib stream, not raw DEFLATE. Its complete returned bytes are counted. The level is explicitly 9. DEFLATE combines sequence matching and Huffman coding, while CHUF models individual byte frequencies. See the [Python 3.13 zlib API](https://docs.python.org/3.13/library/zlib.html#zlib.compress) and [RFC 1951](https://www.rfc-editor.org/rfc/rfc1951.html).

## Synthetic corpora

Every input is generated by `scripts/run_study.py` and committed with its SHA-256 hash. There are no external datasets, scraped documents or personal records.

| Corpus | Construction | Purpose |
| --- | --- | --- |
| `empty.bin` | Zero bytes | Defined empty representation; ratio remains undefined |
| `small.txt` | One owned 26-byte literal | Framing overhead on small data |
| `single_symbol.bin` | 65,536 copies of A | Singleton format policy |
| `skewed_symbols.bin` | 65,536 seeded choices over A/B/C/D, weights 12/2/1/1 | Skewed symbol distribution |
| `uniform_seeded.bin` | 65,536 seeded pseudorandom bytes | Near-uniform histogram without designed repetitions |
| `byte_cycle.bin` | The 256 byte values repeated 256 times | Uniform histogram with strong sequence structure |
| `structured_records.jsonl` | 1,800 fabricated compact JSON records | Repeated fields and delimiters |
| `repeated_text.txt` | 1,400 numbered lines cycling four owned sentences | Repeated phrases and line structure |

The generator uses seed `20261120`. Its shared `random.Random` instance produces records first, followed by skewed and uniform bytes, so the order in the source is part of reproduction. This is a deterministic synthetic fixture, not an assertion of cryptographic randomness or a representative sample of real files. Text files are written as explicit UTF-8 bytes with LF newlines. Git attributes preserve the corpus bytes verbatim.

## Size accounting

The size ratio is `encoded container bytes / original bytes`; smaller is better. Empty input has no ratio. CHUF size includes its 28-byte fixed header, two bytes per symbol, payload bytes and final padding bits. zlib size includes all bytes returned by its default wrapped interface.

For each CHUF stream, the summary records the header-plus-table byte count and the meaningful payload bit count separately. The independently decoded result must exactly equal the source bytes before the run is accepted. Both methods' complete binary outputs are preserved, not just their sizes.

## Entropy interpretation

For byte frequencies `f_s`, input length `n`, and empirical probabilities `p_s = f_s / n`, the reported histogram entropy is:

```text
H_hat = -sum(p_s * log2(p_s))
```

`n * H_hat` is a lower reference for total code length under a symbol-by-symbol prefix model using the observed weights. It is not a universal lower bound for a finite file, nor a promise of an achievable storage size. It omits model transmission, framing and padding. It also ignores correlations: a sequence-aware compressor can legitimately beat this byte-histogram reference. The byte-cycle fixture demonstrates this distinction.

CHUF's singleton policy assigns one bit per symbol even when the histogram entropy is zero. Empty input reports zero entropy by an explicit convention. No statistical inference about a source distribution is made from these fixtures.

## Timing protocol

1. Generate each input and its encoded outputs outside the timed region; verify both decoders return the source.
2. Warm each of the four exact encode/decode operations once.
3. Run seven repetitions. Shuffle the four operations independently each repetition using fixed operation-order seed `55130`.
4. Time each complete function call with `time.perf_counter_ns()`. Codec construction and validation are included. File I/O, output equality assertions and report rendering are excluded.
5. Record every elapsed nanosecond count in `measurements.csv`; derive the median, minimum and maximum without removing observations.

The preserved run contains `8 corpora × 4 operations × 7 repetitions = 224` rows. Graph whiskers are the observed minimum and maximum, not confidence intervals. There is no CPU affinity setting, process isolation, garbage-collector manipulation or background-load control. OS scheduling, machine state, Python build and zlib version can affect results. New runs should be expected to have different timings. CI uses a three-repetition smoke experiment and no performance thresholds.

## Provenance and reconciliation

`environment.json` records the actual UTC start/end timestamps, Python version, OS family, architecture, zlib runtime version, seeds, repetition count, measurement scope and normalized source hashes. Hashes cover the codec and measurement script as they existed before the measured calls. For these two source hashes, CRLF and CR bytes are normalized to LF before SHA-256. Corpus and encoded-output hashes use exact file bytes with no normalization.

The original published run is preserved under `results/published/`. The source refuses to overwrite a directory that already contains a measurement file; default fresh output is `outputs/latest/`. Validation recomputes binary outputs' hashes and decoded bytes, entropy, bit counts, sizes, ratios, raw timing counts, medians and extrema. It also checks the normalized hashes against the current measurement source. A later change to that source therefore requires an explicitly new measured run before declaring the artifacts reconciled.

## Software and limitations

The codec and experiment use the standard library. Plotting uses NumPy `2.3.5` and Matplotlib `3.11.2`, pinned in `requirements.txt`. The published execution environment is recorded separately from these renderer dependencies.

This is a small, selected synthetic corpus. It cannot establish behavior on all files, all machines or competing implementations. The format is intentionally inspectable and bounded, but it has no interoperability certification, external security audit or production deployment evidence. Seeded malformed-input checks supplement deliberate rejection tests; they are not a substitute for sustained fuzzing. The project was developed with AI assistance.
